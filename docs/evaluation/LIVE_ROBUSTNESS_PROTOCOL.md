# HydroSwarm End-to-End LIVE Robustness and Scalability Characterization

## Frozen protocol

This is Study 2. It characterizes the released HydroCore-v4 system through the production API/service path; it is not an extension or replacement of Study 1's offline tensor characterization. Study 1 remains useful for frozen-tensor localization evidence, but it did not invoke live active sampling, planning, WNTR verification, persistence, or wall-clock workflow measurement.

The system under test is production baseline `e45f72cf730d3f12c13dbcb9403c64f185510173`. This branch may add only evaluation harnesses, evaluation-only fixtures, reports, tests, and documentation. It must not alter runtime scientific or authority behavior. No result may cause a model, calibration, threshold, policy, feature, or simulator change.

## Population and fixture ownership

The principal population consists of deterministic WNTR simulations made from the committed, non-locked `golden_network.inp` reference network, the committed `loop-grid.inp` governed topology, and the committed development-only `branched-loop.inp` topology. The latter is the pre-existing unfamiliar-topology control. Evaluation-only generated network sizes, if used, are constructed in a temporary directory by the existing governed generator, tagged `evaluation_only`, physically validated through WNTR, and never written to a corpus split.

Each scenario is generated by `WNTRScenarioGenerator` with a fixed seed, then transformed only in-memory into API observation payloads. Initial evidence and any acquired sample retain their known simulated truth for measurement only; truth is never supplied to the product API. The runner uses the production endpoints for network import, incident creation, analysis, sampling, re-analysis, planning, verification, and the controlled approval/persistence trajectory.

The runner rejects a network, split, fixture, or path containing `locked_final_test`, `locked_topology_test`, or a `test` split. It reads the existing freeze manifest's boolean only, before and after the campaign; it never opens, enumerates, hashes, or consumes locked examples.

## Predeclared matrix

Seeds are 7101--7124 for the reference population, 7201--7208 for unfamiliar topology, and 7301--7306 for scale fixtures. Every condition has one warm-up excluded from aggregates and three timed repetitions unless an explicit timeout, API failure, or WNTR convergence error is recorded. The intended bounded matrix is a scientifically interpretable set of roughly hundreds of API incident runs:

| Family | Predeclared levels |
| --- | --- |
| Nominal control | clean operational evidence; 4 seeds on each governed topology |
| Missingness | 0%, 10%, 25%, 50%, 75%; 4 reference seeds |
| Sensor coverage | full, approximately 75%, 50%, 25%; deterministic sorted sensor subsets; 3 reference seeds |
| Sensor health | one sensor, 25%, 50%, majority, all available sensors degraded; each for quality, drift, frozen, delayed, and communication/missing where valid; 2 reference seeds |
| Noise and bias | nominal, moderate, severe governed noise; positive and negative concentration bias; 3 reference seeds |
| Hydraulic mismatch | demand, roughness, tank-state, source-strength, and timing shifts supported by the existing generator; 2 reference seeds |
| Ambiguity/conflict | deterministic near-tie, contradictory-reading, and high-classical/neural-disagreement fixtures; 2 reference seeds |
| Topology familiarity | governed reference and existing development-only branched topology; 8 seeds on the latter |
| Scale | small reference, medium committed `loop-grid` topology, and largest valid evaluation-only generated network when generation/validation succeeds; 3 seeds |

If a declared condition cannot be represented without invalid sensor semantics, locked data, or a non-convergent physical model, it is recorded as `INCONCLUSIVE` or `HARNESS_ERROR`, never silently replaced by a favorable condition. Conditions that attempt to use all observations as missing retain valid API evidence records with `missing=true`; no fake zero measurements are used.

## Measurements

One machine-readable row is retained per API incident/repetition. Nested sample and plan records preserve individual decisions. Recorded identities include Git, artifact hashes, network hashes, generator seed, platform, WNTR and EPANET exposure. Primary source metrics are top-1, top-3, reciprocal rank, true-source probability, conformal truth coverage, candidate-set size, and entropy. Governance records include classical/neural/fused beliefs, fusion trust, JS disagreement, calibration state, OOD components/level, evidence sufficiency, planning authority, action, and suppression reasons.

The runner measures API-visible analysis and per-stage wall-clock timings; where the live analysis reports internal component timings those are retained without substitution. RSS before/after is recorded along with sampled high-water `peak_process_rss_mb` during the trajectory. The report uses median, min/max or IQR, and p95 only when the group has at least 20 timed measurements. Durations are rounded for display, not altered in raw JSON.

For real sampling, every round records posterior/entropy/candidates before and after, the product's recommended node, product-provided expected information gain, the simulated observation acquired after the recommendation, and stop/continue state. A random-valid-node comparison is performed only if the same scenario has at least two valid unsampled nodes and the same budget; it is labelled an evaluation baseline, not a product mode.

Planning is attempted only through the API when real authority permits it. Every proposed plan records deterministic screening status, exact WNTR result, consequences when exposed, latency, and simulator calls. Controlled lifecycle rows also attempt current verification, stale-verification invalidation, and approval, with no infrastructure actuation.

## Safety invariants and classifications

The runner mechanically checks INV-1 through INV-10 from the study request: suppressed incidents cannot generate plans; unsupported contexts cannot gain authority; verification is required/current before approval; rejected or abstained plans are not approvable; evidence mutation stales verification; and LIVE/REFERENCE provenance remains distinguishable. An explicit invariant holding is `PASS`; an invariant violation is `FAIL`; an adverse but safe measurement is an `OBSERVATION`; a known scope boundary is a `LIMITATION`; and an unanswerable condition is `INCONCLUSIVE`. Harness faults are `HARNESS_ERROR` and trigger complete reruns of affected rows after correction.

The timeout is 120 seconds per API stage and 300 seconds per complete trajectory. A timeout, WNTR/EPANET convergence failure, or unexpected HTTP failure retains a row with unavailable metrics as `null`, its error class, and all prior stage measurements. No retry is substituted for a failed timed row; retries used to diagnose a harness defect are separately identified.

Any genuine product defect is assigned `ROB-LIVE-XX`, preserved with a minimized reproduction and affected rows, and not remediated on this branch. An unresolved HIGH or CRITICAL product finding requires a `DO NOT MERGE` recommendation.

## Reproduction

The one-row harness smoke run executed before the population campaign was an implementation check, not a result-bearing protocol row; it is excluded from every artifact and its output is replaced by the complete frozen campaign. The protocol's explicit loop-grid identity was committed before the population campaign. Execute:

```bash
python scripts/run_live_robustness_characterization.py
pytest -q tests/evaluation/test_live_robustness_characterization.py
```

The generated result artifacts, their exact command, and the frozen identity manifest are the authoritative record; this narrative never substitutes policy reconstruction or model-only timings for a live measurement.
